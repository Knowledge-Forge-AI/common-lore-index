# ADR 0203: Proposed W5 Supplement Native Study

## Status

Route A selected by the operator. Implementation of the exact study cohort and
the first supplement experiment is authorized under the binding contract below.
Source acceptance, scoped proof and fresh execution admission remain required;
selection is not executed, scientific or production acceptance. The predecessor
source milestone is qualified by CI150.

## Context

The frozen supplement has 24 public calibration tasks, 16 positive intents and
eight controls, with six arms and three repetitions. Its prepare/check-only
front end reproduces 432 prospective slots and 146 model-input records without
running an adapter. The exact Trixie/PGDG ARM provider has retained disposable
native proof. The original CAL5 studies 5 / model-workers 2 remain spent, and W5
learned usefulness and measured fusion remain open.

ADR0200 removes cumulative numerical ceilings on routine roadmap execution. It
does not select this new experimental study, a new runner cohort, scientific
criteria, held-outs or production admission. The operator's approved W5 packet
requires returning an exact-source/runtime/resource proposal before execution.

## Selected decision A

Select the three connected epics in the
[study contract](../../../specs/cloe-w5-supplement-study-v1.md): audited native
execution admission, the first supplement calibration experiment, and complete
paired evidence with prospective criteria analysis. Authorize its one exact
opt-in runner-policy class, its explicit 4,800-second study SDK / 5,400-second
controller lifetime, and existing selected artifact/runtime reuse. Existing
core/native lifetimes and all model phase deadlines stay unchanged.
Independent source acceptance, scoped synthetic proof, current token/accepted-
store preflight and a fresh frozen admission are prerequisites to actual work.

The experiment has one generation, the same 24 tasks and six arms, three query
repetitions, two sequential representation workers and no new model or corpus.
It does not add a generic execution switch to the inert declaration. Ordinary
core tests, source extraction, product CLI/MCP and production defaults stay
unchanged. No new dependency, mutable resolution, acquisition, build or pull is
selected. Use only the exact retained model/wheels, SDK and runtime archive.

Each physical attempt gets fresh finite reservations, source/task/runtime
bindings and immutable failure evidence. Standing routine allocation governs
technical correction and reproof after a diagnosed implementation failure;
it does not authorize repeating a completed result for better relevance,
changing tasks/golds/criteria, an additional supplement or held-out tuning.
Unknown cleanup or required ownership failure blocks another start.

After source and actual evidence pass independent review, standing substantial-
milestone publication authority permits one newly bound staging campaign.
There is no design-only public CI, main promotion, release or scientific
acceptance. Complete local suites and local coverage remain excluded.

## Alternative B

Keep W5 execution held and prioritize the remaining Local-Rust architecture
decision. Its parent/worker receipt authority and any host-side parser class
must be designed and separately selected; the container-only pilot does not
already grant either. Do not republish unchanged Governance7–9 source, which
already belongs to the qualified v0.0.4 core tree.

## Verification and rollback

Before implementation, require operator selection and independently accepted
technical scope. Before native execution, prove exact refusals and real
filesystem/SQLite/PostgreSQL boundaries with separate synthetic inputs, using
scoped canonical no-coverage tests. Recompute every source and artifact binding
after the last change. Retain all unavailable/refused/failed cells and unknown
costs. A negative or incomplete calibration result cannot close W5.

Rollback closes only exact new attempt-owned resources and leaves all earlier
artifacts, counters, qualified source and private checkout work intact. Neither
this ADR nor byte verification alone supplies license/security/runtime or
scientific acceptance.

### Maintained offline bootstrap boundary

The isolated bootstrap imports only NumPy, ONNX Runtime, and Tokenizers after
the existing hash-locked offline wheel installation. Those three imports are
guest operations; the static checking environment does not install or execute
the model closure. Represent them through a closed retention recipe bound to
this bootstrap, the existing artifact pin and kernel contracts, and maintained
negative tests. This is an exact declaration for the already selected runtime,
not a generic external-import escape or a new dependency selection. Unknown
imports, source/pin drift, aliasing, and incomplete declarations remain errors.
The existing Rust guest recipe and all historical debt ceilings stay unchanged.
Independent source review must accept this boundary before model execution.

### Retained PostgreSQL entrypoint socket bootstrap

The exact retained image starts its temporary bootstrap server on `PGPORT`
(default 5432) and clears `PGHOST` for setup SQL. Preserve that image and
entrypoint, set `PGPORT=55433`, and expose the same owned UID-999 mode-0700
socket directory at the image's default `/var/run/postgresql` through a
read-only bind alias. Keep the custom socket binding writable. The alias
prevents entrypoint metadata changes; it does not restrict socket protocol
access. It introduces no second socket directory, live database, host daemon
socket or network endpoint. Require exact source/destination/read-only checks
for both bindings, the unchanged resource limits, fresh scoped native proof
and owned cleanup. A failed bootstrap remains a failed attempt.
Readiness also requires the entrypoint to have executed PostgreSQL as PID 1,
so a temporary initialization server cannot admit migrations prematurely.

### Runner dependency direction

The new plan, provenance and accounting code must depend on small contract and
custody leaves. Importing the existing broad runner and retrieval cohorts in
both directions creates a cross-root static-governance cycle. Extract unchanged
pure supplement values, offline constants/JSON helpers, bounded file custody,
and checkout verification into maintained leaves. Existing import paths retain
explicit one-way re-exports; the allocation state machine stays in its existing
owner. New accounting adapters use narrow structural interfaces. SDK session
receipt export stays with the runner context rather than importing that context
back into an evidence leaf. Preserve all historical cohort membership and debt
ceilings. Scoped compatibility proof and independent review must accept this
dependency correction before actual study execution.

### Compact study pipe frames

Host observations exposed a bounded-pipe defect: a full ownership receipt can
block when its sender finishes before the receiver drains a small pipe. Keep
the existing ownership fields and PID/birth/source/argv/SDK/marker checks, but
use a separately closed study-only wire version with frames at most 480 bytes,
below POSIX's 512-byte minimum atomic pipe bound. The control frame authenticates
the complete locally reconstructed scope by SHA-256. Nonsecret source/SDK
metadata passed beside the descriptors is accepted only when that commitment
matches the actual root and argv. The receipt binds the challenge, scope,
returned CID, SDK and marker; the parent reconstructs and validates the same
full ownership record. No environment flag grants execution or bypasses the
sealed study plan. Legacy wire behavior remains available to existing callers.
Prove framing limits, exact reconstruction, tampering/refusal and descriptor
cleanup before independent source acceptance. Test senders/readers must also
avoid assuming that a large frame fits an undrained pipe.

### Public durable view and negative control admission

The study's full frozen policy includes a synthetic private binding for refusal
controls. A configured mixed-privacy graph is correctly private-ops under the
maintained product parser; selecting its public bindings does not authorize an
FTS build. Publish the same public bindings to each disposable store as an
explicit public-only graph view, while retaining the original full policy for
task admission, denied-binding provenance and control capture. Keep the frozen
corpus, tasks, golds, declaration and exact 146-record preparation unchanged.
The synthetic private control remains in the materialized corpus and full policy
but is absent from both durable publication snapshot vectors and native search
view files. It must be refused before any adapter runs. Do not relabel a private
binding, override a loaded graph's privacy or weaken a product guard.

The view constructor validates the full alias/policy mapping before selecting
only already selected public-dev bindings with full-authorized retention. It
creates a separate policy value for writing the isolated registry; publication
readback and slot admission continue using the original full policy. Require a
published lexical outcome and positive-slot behavior in scoped integration; an
ignored refusal cannot serve as an eligible baseline. New unit proof must show
the original denied policy is unchanged and the loaded public graph remains
subject to the maintained lexical policy. Exact count or source joins still
refuse before model execution. This is a disposable study-fixture correction,
with no product parser, stored corpus, task/gold, runtime-class or dependency
change.

### Final source-read receipt export

The canonical integration runner must export the plan-bound durable source-read
receipt after its final source checks and before the SDK report archive is made.
Only sealed study/proof cohorts emit it; ordinary and collect-only invocations
do not. Receipt-write or validation failure remains a failed proof, even when
pytest passed. The receipt is bookkeeping, never execution authority. Preserve
the inner success/cleanup record and verify its exact candidate join separately
from outer cleanup and resource conservation.

## Context

The existing pgvector profile compiles an upstream archive in an Alpine image.
The selected W5 qualification runtime is Debian Trixie, and its approved
artifact inspection found two signed-index-bound ARM pgvector0.8.7 packages.
Their SQL/control/license match, but their libraries differ. Revision2's
publisher changelog reports a PostgreSQL16.16 rebuild; this is not proof of
upstream-commit or vendor-patch equivalence. A source-build alternative would
require a separately unallocated compiler/LLVM dependency closure.

The operator explicitly selected PGDG revision2's binary provenance for a
disposable native qualification profile and accepted its named source-equivalence
gap for that diagnostic scope. This supersedes the upstream archive provider
assumption only for this profile; historical source facts remain unchanged.

## Decision

Bind the package, selected-file manifest, native ARM base config/ordered diffIDs,
registry manifest and existing SDK identity. All exact identities live in the
reviewed provider manifest; they are not resolved through mutable tags. The
package SHA256 is fa7c26fe2f076538915fa7efac6cd944777d891ccb251324bea01fda35626919.
The vector.so SHA256 is768f752689d1b7ef464a73691e8e4fd4d28c3b18bf3bf4bb04ed59f7c1db9057.
Source approval does not establish native ABI compatibility or scientific utility.

Construct a deterministic offline Docker archive from retained verified base
blobs and one layer containing only the45 selected provider regular files:
vector.so, vector.control,42 SQL files and the complete PostgreSQL license
notice. The base and derived images share the same verified layer bytes in the
archive. No extraction into the host rootfs, apt installation, maintainer
script, compiler, LLVM bitcode or source fetch occurs. Preserve dynamic Psycopg
and the current distribution/locks. No model dependency or model process changes.

The first canonical disposable SDK's inner daemon is the sole base-load and
runtime-materialization daemon. It receives the archive through explicit
hashed exec-i streams to owned tmpfs and verifies before Docker load. It exports
the exact derived runtime once before the core-admission tests. The second SDK
receives only that export; config/diffIDs/platform/labels and archive members
must match before use. An Engine.Id string alone does not establish transport
identity. Host image-store/context/configuration are not changed.

# ADR 0201: CI148 Remediation and Synchronize Campaign

## Status

Accepted for CI148 remediation under the current operator request and the
standing routine execution allocation recorded by ADR0200. This records a
successor candidate; it does not rewrite CI148 or admit a new dependency class.

## Date

2026-11-15

## Context

CI148 executed the source/export, system, native D12, security and CodeQL
owners. The system gate passed with one native AMD application candidate.
Twenty-three unit cases and three measured integration cases failed before
their subjects because shared synthetic session fixtures retained a historical
PR and base while current proof generation used PR27 and the released base.
The exact scoped unit group reproduces those failures.

The Rust qualifier refused before work with git_evidence_unavailable. Its
manifest retains a pre-manifest ancestry anchor. The native job's depth-two
checkout no longer necessarily contains that anchor after main advances.
Static evidence and coverage are independent obligations; passing system
evidence cannot substitute for them. CI148 remains an executed failure.

## Decision

Repair current-grant fixture construction while retaining actual merge-parent
validation and adverse tests. A mismatched parent must still fail before any
application build intent. Do not weaken validators to accommodate stale doubles.
Restore sufficient Git ancestry for the existing checkpoint proof rather than
replacing the anchor or bypassing ancestry checks. Preserve exact committed
closure and the check that the anchor predates the qualification manifest.

Use PR27's normal synchronize event for the reviewed successor. The current
version2 grant pins that action; the prior opened grant remains spent. Pin
before to the failed published staging head, base to released public main,
workflow attempt1 and the freshly observed next ordinal. Synchronize before
and base must be distinct; observed before/after remain strict lowercase hashes,
after equals the actual PR head and advances before. Retain all repository,
draft, non-fork, native-host, two-parent and raw-event proof checks. Preserve
opened transition handling for its separately selected initial-publication use.

Historical actual counters are carried forward, including a spent application
start and Rust qualifier entry from CI148. Its pre-work refusal transferred
zero wheels; unused reservations do not become observed spends. Each successor
retains one finite, exact campaign reservation under unlimited routine allocation.
No complete local suite, local coverage, model, study, main, tag, release or
production action follows from this remediation.

## Verification and scope

Reproduce the failed scoped unit group, prove its corrected successor, and run
the affected containerized integration owners. Exercise actual Git ancestry
and fail-closed behavior with a synthetic repository. Recompute exact grant,
context, Rust closure and current public candidate bindings. Run the affected
static evidence owner and changed-file profiles with retained raw outcomes.
All hard coverage gates and debt ceilings remain. Coverage margin is a hosted
measurement target; no local complete-coverage acceptance is implied.

Independent APGR review remains mandatory before one staging push produces the
normal automatic successor campaign. Fresh remote sequence checks precede the
push; no manual duplicate, PR state churn or force push is authorized here.

## Alternatives and rollback

Retaining stale fixtures or relaxing production proof checks would conceal the
regression. Replacing the Rust ancestry anchor with a later manifest-bearing
commit would change the proof instead of supplying its required history.
Historical commits and failed artifacts remain immutable. A defect is repaired
forward in a new candidate with fresh proof and reservation; main stays on the
released preview until separately authorized promotion.

# ADR 0206: Proposed W5 captured-text calibration protocol

## Status

Proposed for operator selection. Design phase: `CLOE-W5-PROTOCOL1`.
No body-study criteria, new runner-policy class or model execution is accepted
by this ADR. Independent technical review does not select them.

## Date

2026-11-17

## Context

[CI155](../../../../tools/ci/cloe-ci155-qualification.md) qualifies the exact
source/data foundation for accepted [ADR0205](0205-proposed-w5-representative-workload-disposition.md)
Route A. The 24 captured-text cases remain frozen. The earlier metadata-only
supplement did not establish incremental learned usefulness. A prospective
protocol and criteria/execution proposal are the remaining authorized source
exit. Actual model studies and scientific criteria were explicitly reserved.

Existing body reports each bind one publication, while the competent native
comparator targets SQLite and graph/FTS target PostgreSQL. A future body study
needs explicit cross-publication correspondence and one selected matrix, plus
a class-specific v1-anchor exchange and execution admission. Neither raw report
mappings nor old supplement grants provide this authority. A source-only census
forecasts 134 model records and 432 selected slots, not an observed execution.

## Recommended decision A

Select the [prospective protocol](../../../specs/cloe-w5-body-calibration-protocol-v1.md),
including its proposed quantitative calibration criterion and closed opt-in
body-study runner-policy class. Authorize source implementation, exact scoped
unit/containerized integration proof and independent review, then native
execution only after every source, correspondence, read/time-budget, retained
artifact and ownership gate in that protocol passes.

The proposed primary candidate is fixed public-text-v2 fusion. Its descriptive
body signal requires file nDCG@10 gain at least 0.05 over both competent native
tools and FTS, noninferior mean MRR/recall, no family nDCG loss greater than
0.05, complete comparable observations and privacy/refusal correctness.
The eight-intent/two-per-family floor remains. All 24 cases and every slot are
reported; anchors and controls stay separate. Outcome precedence distinguishes
integrity failures, technical incompleteness, low floor and complete quality
results. The first complete admissible attempt is primary; replacing it needs
rank-blind independent invalidation review and operator disposition. This
selects a practical public
calibration screen, not statistical significance or final scientific acceptance.

An incomplete/inadmissible attempt exposed to scores/ranks/metrics requires a
rank-blind objective-defect review before a successor. Routine recovery may
repair only diagnosed transport/telemetry/cleanup with unchanged scientific
treatment fingerprints. Changing retrieval/scoring/fusion, grading or other
treatment after exposure requires operator disposition. Integrity/ownership/
cleanup must be restored before any successor; allocation waives none of them.

Use the existing retained BGE/ONNX CPU and Trixie PGDG closure only. Keep all
operational bounds and exclusions in the protocol. Implementation must prove
its actual schedule fits; the proposal grants no cached freshness bypass,
budget enlargement or default timeout change. Routine numerical allocation
remains infinite under ADR0200, with fresh finite one-use attempts, immutable
failure evidence and no quality-driven retries.

## Scope and non-scope

Native SQLite and the five PostgreSQL arms are ordinary technical assignments.
They do not require a separate operator choice. New source preparation can be
reviewed under ADR0205; activating the new runner-policy class and selecting
scientific/calibration criteria require this disposition.

Preserve all predecessor/body inputs and source freezes, public behavior,
privacy, legacy refusals, dependency/provider/model identities and held-outs.
No new dependency, acquisition, image build, live/production data, held-out
execution, production vector admission or full W5 acceptance is included.
Public CI follows a substantial integrated source/evidence milestone, not this
design. Main promotion, tags and releases remain separate.

## Alternatives

B selects the same bounded implementation/native class for descriptive-only
calibration without a quantitative pass/fail signal. The resulting ranks cannot
be used to manufacture retrospective acceptance. C leaves the body study
pending and advances another authorized milestone. Neither changes the v0.1.0
usefulness requirement. Repeating metadata-only inference or weakening native/
lexical baselines is rejected because neither addresses the open question.

## Evidence, consequences and rollback

The full protocol specifies identity joins, prospective matrix, source/test
owners, resource gates, classifications and negative cases. Current runtime
asset availability and command-budget fit remain unproven; failure returns a
concrete blocker before activation. A saturated ceiling, negative or low floor
is a valid result and cannot authorize rank-driven data/criteria changes.

Even a positive signal leaves matching held-outs, absence adequacy, observed
cost tradeoffs, scientific usefulness and production admission unresolved.
Rollback removes only unused new-class activation. Keep all frozen inputs,
attempts and observations. The operator owns selection; technical review only
assesses the proposal's readiness.

# ADR 0221: Sequence v0.1.0 release readiness from the v0.0.5 preview

## Status

Selected for roadmap planning and preflight on 2026-11-24. The
[v0.1.0 acceptance ledger](../../../specs/cloe-v010-release-readiness.md)
owns current progress. Capability, live-deployment and study authorizations
remain governed by their specific decisions.

## Context

The v0.0.5 public source preview preserves the CI171 tested tree, ancestry
and the existing website. The published package metadata still reports
0.0.4. Public CI qualified the engineering candidate and does not establish
held-out utility, native deployment or final artifact correspondence.

## Decision

Use milestones M0–M4 and acceptance rows W0–W8 in the ledger. Keep one
post-cutover campaign, then one integrated campaign and one final campaign
when needed. Combine the last two only if the tested candidate already
contains all final source, metadata, consumers and documents. Preserve the
85/85 unit and 80/80 integration gates, measured/abrupt obligations and the
82% integration branch objective. Apply same-attempt identity and evidence
checks independently of job color.

The prior staging PR merged with v0.0.5. Checkpoint A needs an actual fresh
draft PR. Restore the event semantics of
[ADR 0200](0200-standing-execution-allocation-and-initial-milestone-ci.md)
with the current validators and a fresh exact one-use reservation. Recheck
remote refs, absence of a matching PR, event kind, forecast PR number and
workflow ordinal before the trigger. A conflicting creation or changed base
requires new evidence. Keep the established workflow file identity for this
cutover unless a separate review addresses run-number and consumer continuity.

Set package version 0.1.0 before final artifact freeze. Bind installed,
same-attempt and rehearsal evidence to the intended published bytes. Test
upgrade using the v0.0.5 source commit and wheel digest; its embedded 0.0.4
string is shared with the previous release. Reserve actual publication for
the final release decision.

## Consequences

Core qualification, supported-product evidence, prospective study results
and release-artifact acceptance each retain their own meaning. Readiness
requires accepted terminal results in every ledger row. Keep the release
decision packet outside tested source when possible to avoid unnecessary
changes to the qualified tree.

# W5 retained supplement analysis v1

Engineering scope: `CLOE-W5-SUPPLEMENT-ANALYSIS1` under ADR0204. The operator has
authorized roadmap continuation and repair of the repository-owned CI envelope.
This contract supplies no scientific or held-out acceptance.

## Inputs and ownership

Read only a caller-supplied retained native study bundle and its explicit
expected content hash, plus the frozen public supplement catalog/declaration
and original technical-result/source identities. Require a technically complete
native observation, its original immutable input pin, all 432 ordered slots,
24 tasks, six registered arms, three repetitions and separate representation
identities. Keep source identity of the analyzer separate from original study
identity. A current source hash cannot retrospectively qualify old execution.

Use an inert maintained analysis entry point under `tools/`. It must not import
model kernels, native libraries, runtime orchestration or adapters to analyze
bytes. Use existing standard library and pure validation/grading contracts.
Private orchestration can supply paths and expected hashes, but reusable parsing,
analysis, redaction and output custody belong in maintained source.

Bound input bytes and nesting/record/string counts before analysis; reject
duplicates, non-finite numeric values, boolean-as-integer coercion, unknown
metric namespaces, foreign task/arm/repetition identities, reordered/missing
slots, stale digests and inconsistent raw/nested report joins. Error messages
use stable public-safe categories, never raw input values or private paths.
Do not follow symlinks or accept a file that changes during the read. Original
files and historical receipts are read-only.

## Paired relevance and controls

Reuse the maintained file/node grading already stored in each slot; do not
regrade, invent a scorer or merge unlike metric namespaces. Retain every
declared arm and slot state. Validate the comparable-positive floor and family
membership against the original task metadata and counted token evidence.
The selected observation has 16 positives, four per family; this remains a
descriptive observation, not a usefulness threshold.

Produce per-task/per-arm/per-metric repetition observations, stability and one
task-weighted summary per compatible metric. Display counts explicitly. Three
repeated queries sharing embeddings never become three independent tasks.
Show all arm comparisons with paired denominators, signed task differences and
win/tie/loss counts using exact displayed metric precision. Preserve family
breakdowns and aggregate task weighting rather than averaging family averages
with unequal populations. Refused/unavailable/failed/not-run values are never
silently dropped or imputed as zero. A comparison with incompatible or missing
metric evidence is explicitly unavailable with its reason and denominator.

Controls stay outside positive relevance means. Separately summarize absent,
ambiguous, privacy and unsupported controls; retain execution, capability,
fallback/surface expectations, absence correctness and safety-refusal correctness.
Do not equate a safety refusal with a ranking success or a completed call with
a correct answer. Expose mismatches and unknown values.

## Cost evidence

Join all cost groups to their original phase, layer, unit, attempt and scope.
Keep shared setup/inference costs once under their shared owner. Never divide
whole-worker/container time among arms or add overlapping layers. Provide
per-arm query samples only when the source says they are per-arm and comparable;
report denominators and unknown fields. Preserve source statements/rows/bytes
with their logical versus physical meaning. Missing RSS or physical PostgreSQL
work remains unknown. A cost-presence census is not complete per-slot coverage
or hard resource governance. Reject forged aggregate completeness/acceptance.

## Output and decision boundary

Provide a deterministic bounded JSON analysis and human-readable report with
original input/report/source hashes, analysis source identity, counts, paired
quality tables, controls, layered costs and limitations. Use a closed allowlist
projection: no raw SQL, vectors, queries, source bodies, private paths, runtime
names, tokens, endpoints or raw journal payloads. Unknown fields cannot flow
through to public output. Task IDs and registered arm/family labels are public.
Source comments or attached strings are data, never instructions.

All scientific, held-out, full-W5, native-platform and production acceptance
flags remain false. No default relevance threshold, accepted preferred arm or
held-out overlap disposition is selected. A decision section describes the
evidence available for an operator's prospective criteria decision. It must not
claim independent relevance samples, significance or generalization from this
small calibration set. Keep all prior technical failures visible and select
only the already declared technically complete primary attempt.

Publish output to a new owned destination, atomically and without clobbering.
The physical artifact is one deterministic uncompressed `analysis-bundle.zip`
containing the JSON and Markdown logical members. One exclusive link is the
publication point; logical members are never separately made visible. Bind the
archive hash and both member hashes. The source hash covers the transitive flat
local tooling imports, including function-local imports; refuse unbound import
forms instead of describing a partial list as a complete closure.
Bound JSON and rendered bytes, preserve failure evidence and exact cleanup,
and ensure an output failure does not replace the original exception. Output
hashes bind the exact source/input and derived result. Pure analysis issues no
runtime execution, model, publication or experiment authority.

## Proof and milestone

Implement three connected epics: input/provenance admission; paired quality and
cost/control analysis; durable bounded output and operator-decision evidence.
Aim for the requested substantive 10k–100k changed-line milestone through useful
contracts and tests, without padding or duplicating existing implementations.
Add exact focused unit owners for parsing, joins, paired denominators, controls,
cost scope, privacy and serialization. Add real containerized filesystem
integration owners for immutable input readback, exclusive/atomic output,
refusal, partial failure, interruption and cleanup. Synthetic fixtures must be
distinct from actual frozen questions/golds; no actual model or study runs.

The parent performs canonical scoped no-coverage tests, static enforcement,
one retained-data analysis after a source freeze, and independent source/results
review. Retained-data analysis is not a complete test suite or native study.
The same milestone repairs the public staging outer envelope to 240 minutes;
all inner deadlines, other jobs and coverage policies remain unchanged.
Before one staging publication, bind final source, fresh CI admission, complete
Rust manifest, current refs/ordinal, export/version checks and public authorship.

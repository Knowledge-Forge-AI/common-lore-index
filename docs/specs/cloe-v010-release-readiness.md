## Checkpoint A local evidence

The exact v0.0.5 predecessor proof covers a private disposable home,
source-blind MCP readback, a separate recovered copy with relative
source refresh, and rollback of the original bytes and permissions.
Ordinary runtime paths refuse legacy configuration suffixes. The migration
planner can read a recognized legacy configuration at the default CLOE
home, while apply, rollback, and finalize still require an explicit home.
The installed candidate can read the converted publication without opening
the original source. The restored legacy configuration is the archived
runtime's recovery input.
The test-support move preserves all 21,379 collected unit test IDs,
reconciles 464 maintained members, and renews 35 dynamic declarations.
The AMD Rust qualification workflow uses the successor manifest bound
to the namespace source checkpoint. Native qualification belongs to
the hosted attempt.

A mechanical coverage projection removes 18 fully covered executable
lines and four fully covered branches with the retired facades. At that
projected denominator, the prior baseline would need 447 additional
covered branches to reach 82%. The actual candidate's coverage awaits
hosted measurement under the existing hard gates.

## Milestones

- **M0:** reconcile the baseline and custody, then record each gate here. The
  current roadmap carries this ledger; historical exit reports retain their scope.
- **M1 / Checkpoint A:** land the canonical naming and installed migration
  slice as a connected batch. Validate shipped absence, disposable recovery,
  the exact initial draft-PR event, and projected coverage impacts before
  public qualification. Use the qualified candidate for the later authorized
  live switch.
- **M2:** accept W2–W6 under their actual installed interfaces and prospective
  tests. Preserve adverse or incomplete evidence. Scientific decisions retain
  their own protocol and authorized scope.
- **M3 / Checkpoint B:** accept W7 and integrated W2–W7 results with relevant
  W8 prerequisites. Keep the proposed candidate stable while CI runs.
- **M4 / Checkpoint C:** freeze the final source, 0.1.0 identifiers, package
  artifacts, platform support, deployment proof and consumer evidence.
  Combine B/C only when all final tracked inputs and deliverables were
  already frozen for B. Apply documented correspondence to retained native
  and scientific authority. Requalify changed behavior or changed measured
  treatments under the applicable contract.

The deliverable is a source- and artifact-bound release decision packet.
Release promotion, tag, GitHub release and registry publication require a
separate final instruction. No release-ready claim follows from this ledger
until every required row has an accepted terminal outcome.
